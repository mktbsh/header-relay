# 監査ログのレベル絞り込み 仕様書

承認済みの[PR/FAQ](./2026-08-13-audit-log-level-filter-prfaq.md)を実装可能な仕様へ翻訳する。
読み出し方法の判断は[ADR](../adr/2026-08-13-audit-log-level-query.md)に記録した。

## スコープ

### 含めるもの

| 項目                                                                      | 根拠                                                                  |
| ------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Audit Logsに深刻度の下限を選ぶセレクトを追加する                          | PRの顧客体験                                                          |
| 絞り込みをIndexedDBの読み出し時に適用する                                 | FAQ「絞り込むと、古いerrorも見つかりますか」                          |
| 深刻度の順序を単一の定数として定義し、`AuditLogLevel`型をそこから導出する | ADR「影響」                                                           |
| in-memoryアダプターへ同じ判定を反映する                                   | 既存の保持期間・URL除去と同じく、両アダプターが同一ポリシーを共有する |
| 空状態に専用の文言を追加し、全ロケールへ反映する                          | 下記 US-03                                                            |
| `header-relay`のpatch changesetを同梱する                                 | FAQ「リリース時の変更種別」                                           |

### 含めないもの

| 項目                                           | 理由                                                                                                  |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| eventまたはProfileによる絞り込み               | 課題は記録量であり、量の大半はdebugが占める。深刻度だけで解ける                                       |
| 選択状態の保存                                 | 監査ログはまず記録の全体量を提示する画面と定める。絞り込みは毎回意図して行う操作にする                |
| 既定値を「すべて」以外にすること               | 同上                                                                                                  |
| 表示件数（200件）の変更                        | 課題は件数ではなく内訳。件数を増やしても読む気は戻らない                                              |
| 記録量そのものの削減（`origin_matched`の抑制） | どのProfileがどのリクエストに反応したかを確かめる唯一の記録を失う。表示の絞り込みで足りるかを先に見る |
| 分析イベントの追加                             | productionでは送信も出力も無効で、現時点の判断材料にならない                                          |
| popupへの反映                                  | popupに監査ログの表示はない                                                                           |
| `by_level` indexの削除                         | 削除にIndexedDBのバージョン更新が必要で、見合う利点がない                                             |

## ドメインモデル

### 深刻度の順序

`AuditLogLevel`は現在`src/lib/domain/types.ts`で4値のunionとして定義されている。
これを`src/lib/domain/audit-level.ts`へ移し、順序付きの定数から導出する。

```ts
export const AUDIT_LOG_LEVELS = ["debug", "info", "warn", "error"] as const;
export type AuditLogLevel = (typeof AUDIT_LOG_LEVELS)[number];
```

配列の並びが深刻度の昇順である、という一点だけが順序の定義になる。
union型を別に書くと、レベルを追加したときに順序の配列と型の片方だけが更新されうる。導出すれば両方が同時に変わる。

判定は配列の添字比較で行う。

```ts
export const isAtOrAboveLevel = (level: AuditLogLevel, minLevel: AuditLogLevel): boolean =>
  AUDIT_LOG_LEVELS.indexOf(level) >= AUDIT_LOG_LEVELS.indexOf(minLevel);
```

### 「すべて」を別の状態にしない

セレクトの4つの選択肢は、深刻度の下限そのものへ対応する。

| 表示      | 値      | 残る記録                    |
| --------- | ------- | --------------------------- |
| すべて    | `debug` | debug / info / warn / error |
| info以上  | `info`  | info / warn / error         |
| warn以上  | `warn`  | warn / error                |
| errorのみ | `error` | error                       |

最小の深刻度が`debug`であるため、「すべて」は`minLevel: "debug"`と同義になる。
`"all"`という追加の状態を持たない。絞り込みなしと絞り込みありで分岐する経路が生まれない。

### 状態

画面が持つ状態は、選択中の下限1つだけである。

| 状態         | 値域            | 初期値    | 遷移                                   |
| ------------ | --------------- | --------- | -------------------------------------- |
| 選択中の下限 | `AuditLogLevel` | `"debug"` | セレクトの変更のみ。画面を離れると破棄 |

## 経路

絞り込み条件は次の7段を通る。各段の変更は引数1つの追加に収まる。

| 段           | ファイル                                                         | 変更                                             |
| ------------ | ---------------------------------------------------------------- | ------------------------------------------------ |
| 表示         | `src/entrypoints/manage/sections/AuditLogSection.tsx`            | セレクトを追加し、選択と変更ハンドラーを受け取る |
| 画面状態     | `src/entrypoints/manage/use-audit-log.ts`                        | 下限のsignalを持ち、変更時に再取得する           |
| クライアント | `src/lib/messaging/client.ts`                                    | `getAuditLogs`に下限を渡す                       |
| プロトコル   | `src/lib/messaging/messages.ts`                                  | `GetAuditLogsPayload`に`minLevel`を追加する      |
| ハンドラー   | `src/lib/messaging/background-handlers.ts`                       | 受け取った下限を渡す                             |
| コマンド     | `src/lib/runtime/extension-commands.ts`                          | `audit.recent`へ渡す                             |
| ポート       | `src/lib/ports.ts`                                               | `AuditPort.recent`の引数に下限を追加する         |
| 実装         | `src/lib/storage/audit-db.ts`, `src/lib/testing/memory-ports.ts` | カーソル走査に判定を加える                       |

`recent`の引数は、位置引数を増やさず単一のオプション objectへ変える。

```ts
recent: (options?: { limit?: number; minLevel?: AuditLogLevel }) => Promise<AuditLog[]>;
```

既存の呼び出し箇所は`extension-commands.ts:232`とテストのみで、置き換えの影響範囲は閉じている。

## ユーザーストーリーと受入条件

### US-01 記録量を減らして原因へ到達する

管理画面のAudit Logsを開いた開発者が、リクエストごとの記録を消して失敗の記録だけを見る。

| ID    | 受入条件                                                                                                                                                     | 検証               |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------ |
| AC-01 | Given Audit Logsに debug / info / warn / error の記録がある。When 深刻度に「info以上」を選ぶ。Then debugの記録が一覧から消え、info以上の記録が新しい順に残る | e2e                |
| AC-02 | Given 同上。When「warn以上」を選ぶ。Then warnとerrorだけが残る                                                                                               | unit（`audit-db`） |
| AC-03 | Given 同上。When「errorのみ」を選ぶ。Then errorだけが残る                                                                                                    | unit（`audit-db`） |
| AC-04 | Given 深刻度を絞っている。When「すべて」に戻す。Then 絞り込み前と同じ記録が同じ順序で表示される                                                              | e2e                |

### US-02 表示件数の外にある失敗を見つける

リクエストの多い画面を操作したあと、直近の記録に埋もれた失敗を探す。

| ID    | 受入条件                                                                                                                     | 検証                                 |
| ----- | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| AC-05 | Given 1件のerrorのあとに、表示上限（200件）を超えるinfoが記録されている。When「errorのみ」を選ぶ。Then そのerrorが表示される | unit（`audit-db`、`fake-indexeddb`） |
| AC-06 | Given 同上。When「すべて」を選ぶ。Then そのerrorは表示されない。表示上限は据え置きであり、絞り込みだけが到達手段である       | unit（`audit-db`）                   |
| AC-07 | Given 一致する記録が表示上限を超える。When 任意の深刻度を選ぶ。Then 新しい順に最大200件が表示される                          | unit（`audit-db`）                   |
| AC-08 | Given in-memoryアダプターを使うテストランタイム。When 同じ条件で引く。Then IndexedDBアダプターと同じ結果になる               | unit（`memory-ports`）               |

### US-03 絞り込み中であることを見失わない

絞り込んだ結果が0件のとき、記録がないのか条件に合わないのかを取り違えない。

| ID    | 受入条件                                                                                                                                      | 検証                                       |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| AC-09 | Given errorの記録が1件もない。When「errorのみ」を選ぶ。Then「この深刻度の記録がない」旨の文言を表示する。既存の「記録がない」文言は表示しない | e2e                                        |
| AC-10 | Given 記録が1件もない。When「すべて」で表示する。Then 既存の`noAuditLogs`の文言を表示する                                                     | 既存の挙動を維持する                       |
| AC-11 | Given 絞り込み中である。Then セレクトは選択中の深刻度を表示し続ける                                                                           | 実装上、選択状態がそのまま表示に反映される |

### US-04 画面を開き直すと全体量から始まる

| ID    | 受入条件                                                                                                            | 検証                                      |
| ----- | ------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| AC-12 | Given 「errorのみ」を選んでいる。When 別のタブへ移動して戻る。Then 選択は「すべて」に戻り、すべての記録が表示される | e2e                                       |
| AC-13 | Given 同上。When 管理画面を再読み込みする。Then 選択は「すべて」に戻る                                              | AC-12と同じ経路（状態は画面のsignalのみ） |

### US-05 記録と保持の扱いが変わらない

| ID    | 受入条件                                                                                                                           | 検証                                    |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| AC-14 | Given 深刻度を絞っている。When「Clear logs」を押す。Then 深刻度に関係なくすべての記録を削除する                                    | unit（既存の`clear`が無変更であること） |
| AC-15 | Given 任意の深刻度を選んでいる。Then IndexedDBへ保存する項目、保持上限（1000件・7日）、リクエストURLを永続化しない方針は変わらない | 既存テストの継続通過                    |
| AC-16 | Then manifestの権限と`AppConfig`のスキーマは変わらない                                                                             | `pnpm build`成果物の確認                |

## 非機能要件

| 項目       | 要件                                                                                                                  | 確認                         |
| ---------- | --------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| 応答       | 深刻度の変更から一覧の更新までが、待たされたと感じない範囲に収まる。「errorのみ」では保持上限の1000件を走査して終わる | 検証タスクT-01（実機）       |
| 権限       | 新しい権限を要求しない                                                                                                | `pnpm build`後のmanifest確認 |
| データ保持 | 記録内容・保持上限・URLを永続化しない方針を変更しない                                                                 | AC-15                        |
| 保存領域   | 選択状態を保存しないため、storageを消費しない                                                                         | 実装上、signalのみ           |

## エッジケースとエラー

| ケース                                                       | 挙動                                                                     | 利用者に見えるもの       |
| ------------------------------------------------------------ | ------------------------------------------------------------------------ | ------------------------ |
| `minLevel`が未指定                                           | `"debug"`として扱う。既存の呼び出しと同じ結果になる                      | 変化なし                 |
| `minLevel`に未知の値が届く（他コンテキストからのメッセージ） | `indexOf`が`-1`を返し、すべての記録が条件を満たす。例外にしない          | すべての記録が表示される |
| 一致する記録が0件                                            | 空配列を返す                                                             | US-03の専用文言          |
| 走査中に保持期間のpruneが走る                                | 既存の`recent`と同じ。カーソルは削除済みの記録を返さない                 | 変化なし                 |
| 深刻度の変更と自動更新が重なる                               | 既存の`refreshing`ガードで再入を防ぐ。変更後の条件で次の取得が走る       | 一覧が一度だけ更新される |
| 展開中の記録が絞り込みで消える                               | 既存の`reconcileExpandedAuditLogIds`が、存在しない記録の展開状態を落とす | 展開状態が残らない       |

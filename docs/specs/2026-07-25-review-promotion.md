# Chrome Web Store レビュー訴求

## 文書の目的

この文書は、Header Relay の管理画面から Chrome Web Store のレビューを促す仕組みの仕様を定義する。

対象となる利用者は、Header Relay を継続的に使っている開発者である。

## 目的と非目的

**目的**

- Chrome Web Store のレビュー数を増やし、ストア内の発見性を高める。
- 不満を持つ利用者の声を、低評価レビューではなくフィードバックフォームで受け取る。

**非目的**

- Popup へのレビュー訴求は追加しない。Popup は作業中に開く画面であり、訴求で滞在時間を奪わない。
- 評価の内容や送信結果を拡張機能側で受け取らない。遷移先は外部サービスに委ねる。

## 配置

管理画面のサイドバー（`lg` で 260px 幅）下部だけを使う。訴求は次の二つで構成する。

### 1. 常設リンク

サイドバー footer のアイコン列（Settings / Homepage / Buy Me a Coffee）の右端に、星アイコンのレビューリンクと吹き出しアイコンのフィードバックリンクを追加する。

- レビューの遷移先: `https://chromewebstore.google.com/detail/olmfkdclaloaacojbgaabokehlbphilf/reviews`
- フィードバックの遷移先: 後述のフォーム URL。訴求カードを閉じたあとでもいつでも意見を送れるようにするためのもの。
- どちらも常に表示し、状態を持たない。表示条件も非表示化もない。
- 既存のアイコンリンクと同じ `hr-sidebar-link`、16px の stroke アイコン、`aria-label` と `title` を持つ。
- フィードバックリンクの `href` は隠しフィールドの値を必要とするため、インストール ID の読み出し後に描画する。

### 2. 訴求カード

サイドバー footer の直上に、状態を持つカードを表示する。

- 表示条件はない。インストール直後から、後述の終了条件を満たすまで常時表示する。
- 幅 260px（コンパクト時はさらに狭い）に収まる文言に限る。1 行あたり全角 12 文字程度を上限とする。

## 訴求カードの動作

満足度を先に聞き、回答によって遷移先を分ける二段構成とする。

### Step 1: 満足度

- 本文: 「Header Relay は役に立っていますか?」
- ボタン: 「はい」「いまひとつ」
- 補助リンク: 「後で」

### Step 2A: Step 1 で「はい」

- 本文: ストアのレビューが他の開発者の助けになる旨を伝える。
- ボタン: 「レビューを書く」→ 上記のレビュー URL を新規タブで開く。
- 補助リンク: 「閉じる」

### Step 2B: Step 1 で「いまひとつ」

- 本文: 改善のために意見を聞かせてほしい旨を伝える。
- ボタン: 「意見を送る」→ フィードバックフォーム URL を新規タブで開く。
- 補助リンク: 「閉じる」

Step 2 は同じカードの中で本文とボタンを差し替える。ページ遷移もモーダルも使わない。

### 状態遷移

| 操作                          | 次の状態                        |
| ----------------------------- | ------------------------------- |
| Step 1「後で」                | 30 日間スヌーズ。以後は再表示   |
| Step 1「はい」/「いまひとつ」 | Step 2 を表示。状態は保存しない |
| Step 2「レビューを書く」      | 完了。二度と表示しない          |
| Step 2「意見を送る」          | 完了。二度と表示しない          |
| Step 2「閉じる」              | 完了。二度と表示しない          |
| Step 2 の途中で画面を離れる   | 状態は変わらず、次回は Step 1   |

スヌーズは繰り返し使える。「後で」を押すたびに 30 日先へ延びる。

## 保存する状態

`storage.local` に `review-prompt` を持つ。

```ts
type ReviewPromptState = {
  // 完了した訴求は二度と表示しない。
  done: boolean;
  // 「後で」で延ばした再表示時刻（epoch ミリ秒）。0 は未スヌーズ。
  snoozedUntil: number;
};
```

表示判定は純粋関数 `shouldShowReviewPrompt(state, now)` に閉じる。`!state.done && now >= state.snoozedUntil` だけを見る。Step 1 と Step 2 の切り替えはコンポーネントのローカル状態として扱い、保存しない。

## フィードバックフォーム

- 無料かつ回答数無制限の [Tally](https://tally.so/) でフォームを作成し、その公開 URL `https://tally.so/r/VLBgdj` を使う。
- フォームは匿名回答とし、必須項目は自由記述の 1 問だけにする。個人情報の入力欄は置かない。
- URL は `src/lib/review-prompt/state.ts` の定数 1 箇所に置く。ストア URL と同じ扱いで、他のファイルへは散らさない。
- 埋め込みはしない。Tally の埋め込みは `embed.js` の読み込み（MV3 で禁じられた remote code）か iframe を要するうえ、260px のサイドバーにフォームは収まらない。新規タブで開く。
- 隠しフィールドはクエリパラメータで渡す。値は `buildFeedbackFormUrl` が組み立てる。

| フィールド | 値                                    | 必須 |
| ---------- | ------------------------------------- | ---- |
| `version`  | `runtime.getManifest().version`       | 必須 |
| `c`        | `local:analytics-client-id`（UUIDv7） | 必須 |
| `ref`      | 流入元（下記）                        | 必須 |
| `obfe`     | 難読化した直前のエラー                | 任意 |

`ref` の値は次の 3 つに限る。新しい導線を足すときはこの union に足す。

| 値                | 流入元                               |
| ----------------- | ------------------------------------ |
| `int`             | 既定値。特定できない場合             |
| `int-bottom-nav`  | サイドバー下部のフィードバックリンク |
| `int-review-card` | 訴求カードの「いまひとつ」経由       |

`obfe` は送出元となるエラー報告導線がまだないため未実装とする。導線を作る時点で `buildFeedbackFormUrl` に引数を 1 つ足す。

## 行動分析

`review_prompt` イベントを 1 つ追加する。既存の closed union の方針に従い、パラメータは列挙値のみとする。

| パラメータ | 値                                                                                 |
| ---------- | ---------------------------------------------------------------------------------- |
| `surface`  | `manage`                                                                           |
| `action`   | `shown` / `positive` / `negative` / `rated` / `feedback` / `snoozed` / `dismissed` |

`shown` はカードを表示した管理画面の読み込みごとに 1 回だけ送る。自由記述や URL は送らない。

## 受け入れ条件

- [ ] サイドバー footer に、Buy Me a Coffee の右横のレビューリンクとフィードバックリンクがある。クリックでそれぞれ新規タブで開く。
- [ ] 訴求カードがサイドバー footer の直上に表示され、Step 1 の本文とボタンが 260px 幅で折り返し崩れを起こさない。
- [ ] 「後で」を押すとカードが消え、30 日後に再表示される。
- [ ] 「はい」で Step 2A、「いまひとつ」で Step 2B に切り替わる。
- [ ] Step 2 のいずれのボタンを押しても、以後カードは表示されない。
- [ ] `shouldShowReviewPrompt` の単体テストがある（未スヌーズ / スヌーズ中 / スヌーズ明け / 完了）。
- [ ] 8 ロケールすべてに文言がある。
- [ ] `review_prompt` イベントが `docs/analytics.md` の表にある。
- [ ] changeset（minor）を同梱する。
- [ ] Popup には一切変更を加えない。

## 決定の記録

- 表示場所をサイドバーのカードにしたのは、Overview のバナーが主作業を遮り、保存フローに紐づける実装が訴求のために保存処理へ分岐を持ち込むためである。
- トリガーを設けず常時表示にしたのは、利用日数や成功回数のカウンタを新たに持たずに済ませるためである。カードの押しつけがましさは「後で」のスヌーズで抑える。
- 二段構成にしたのは、不満を持つ利用者をストアの星ではなくフォームへ導くためである。
